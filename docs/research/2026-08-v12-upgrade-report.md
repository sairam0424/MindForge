# MindForge v12 — Upgrade Research Report

## 1. EXECUTIVE READ

v12 should be **smaller and truer, not bigger**. MindForge's advertised identity — an enforced agentic operating protocol — rests on ~500 LOC of hooks, and I verified those hooks are registered on **zero installs**: `.claude/settings.json` is not among the 47 entries in `package.json` `files[]`, and no code in `bin/` writes or merges one (`grep -rn "settings.json" bin/` returns reads only, including `bin/harness-audit.js:335` which names the gap as an unfixed remediation). The plugin channel — which `README.md:14-19` calls the "Fastest path" — crashes on every hook fire because `plugins/mindforge/scripts/lib/` does not exist. So both advertised install paths ship the instruction corpus with none of the enforcement, and the product's positioning is currently unsupported by its own runtime.

Against that, one asset is genuinely best-in-field: `node bin/verify-audit.js` → `✅ audit chain valid: 1934 entries`, from a 12-line hasher shared by writer and verifier. That, plus real SLSA provenance on npm, is what v12 should be built and marketed on.

**Biggest strategic risk:** MindForge is competing on breadth (swarm, neural, memory) against ruflo at 10× scale while its own differentiator — verifiable governance — is being commoditised by spec-kit governance presets across 35 harnesses. Continuing to add surface, rather than making the enforced boundary real and provable, loses both races.

| **Take a hard dependency on `sigstore-js`, `transformers.js`, `tree-sitter`, or `@haldir/*`.** | `sigstore-js` 5.x requires Node `^22.22.2\|\|^24.15.0\|\|>=26`; `transformers.js` is ESM-only and exact-pins `onnxruntime-node`; tree-sitter reintroduces native builds in the same release that justifies itself by dropping to one runtime dep; `@haldir/*` is v0.1 single-vendor with a modified DSSE PAE that generic verifiers cannot read. Adopt the *shapes*, not the packages. |
| **Adopt DiskANN in `sqlite-vec`, or a caret range for it.** | ANN indexes are alpha-only; the `latest` dist-tag has previously resolved to prereleases. At MindForge's scale (2,038 + 5,640 + 12 rows) brute-force cosine is the correct answer with perfect recall. |
| **Replace SQLite with LanceDB / Orama / Turso / DuckDB.** | Orama reproduces the exact whole-file-rewrite defect being fixed; the others are store migrations, not driver swaps, and each adds a native or format dependency that breaks the "npx and it works" promise. |
| **Ship a `sandbox` block from project scope.** | `strictAllowlist` has **no effect** in `.claude/settings.json` — it must be user, managed, or `--settings`. A project-scope write produces a config that looks hardened and is not. |
| **Shorten hook timeouts before measuring.** | Two probes on the same build disagree on whether a PreToolUse timeout fails open or closed. If it fails closed, 5000→5 turns an invisible non-issue into visible unexplained tool-call denials. Instrument `duration_ms` first, set p99+50%. |
| **Chase `gitlab`, `settings` or `directory` plugin source types.** | They do not exist. GitLab is reached via `url` with an explicit `https://` prefix and `.git` suffix. |
| **Introduce `archive` or `command` marketplace sources without a version floor.** | `archive` needs 2.1.224+; on older builds a marketplace *containing* one fails to load **entirely**, taking the whole catalogue down. |
| **Quote any vendor LoCoMo / LongMemEval number in MindForge's docs.** | The independent spread on one benchmark is 45 points; 6.4% of LoCoMo's answer key is wrong. |
| **Register 355 skills natively without `paths:` and a bare-name collision audit.** | Up to 355 descriptions enter every turn's context, and several bare names (`tdd`, `brainstorming`, `using-git-worktrees`, `writing-skills`) collide with widely-installed plugins. Note a project skill overrides a bundled skill but **never its aliases** — `/review` will never be MindForge's even if `/code-review` is. |
| **Pursue Single Executable Applications.** | SEA's injected `require()` resolves built-ins only; 174 dynamically-required modules break at once, and macOS x64 + Alpine are untested upstream. `npx` already gives zero-install distribution. |
| **Delete `sdk/src/memory.ts` in v12.** | `mindforge-sdk` is published with 6 versions and exports `MindForgeMemory`. Extract the shared checksum; deprecate the export in its own major. |
| **Fix `graph_edges` with a tree-sitter code graph.** | `graph_edges` is empty because a migration never ran over a file (`.mindforge/memory/graph-edges.jsonl`) that has never been written — not because of the casing bug. Fix the 2-line latent bug; do not build a code-graph product. |

## 10. OPEN QUESTIONS FOR THE USER

1. **Is the enforced boundary the product, or is the corpus the product?** If enforcement is the product, REG-01 is the whole of v12 and the markdown corpus should shrink by ~70%. If the corpus is the product, delete the enforcement claims from `README.md:3`, drop "zero-trust", and position MindForge as an instruction framework — which is defensible and much cheaper. **You cannot ship both stories in v12.** Everything in §4 assumes the first answer.

2. **Six harnesses, or two done properly?** Cursor and Copilot CLI both have blocking hooks, so 3/6 real enforcement is reachable cheaply. Reaching 6/6 means owning six config formats forever. The alternative is to declare Claude Code + Cursor + Copilot as *enforced* tiers and Gemini/OpenCode/terminal as explicitly *advisory*, documented per-gate. That is honest and halves the adapter surface — but it retires a headline claim.

3. **How much breakage will you spend?** The full v12 set is: `engines >=22.14.0` (refuses install on Node 18/20), the addressing codemod, 7 skill renames, adapter rewrites, and a `plugin.json` bump that lands frozen marketplace users on live security gates. That is one large, well-documented major. The alternative is two majors (v12 = enforcement + honesty; v13 = engines + structure), which halves each blast radius and doubles the elapsed time.

4. **Do you unstick the frozen plugin installs?** Bumping `plugin.json` from 11.5.1 is what delivers the fix — and simultaneously activates security gates that have never fired on those machines, on a codebase four minors newer. The safe alternative is to publish under a new plugin name and use the marketplace `renames` map, accepting that some installs never migrate.

5. **Do the phantom capabilities get implemented or deleted?** `SwarmController`, `PersonaFactory`, `soul-engine.js`, `shard-controller.js` are instructed and absent. Implementing them is a multi-release product bet against ruflo's 237+ MCP tools. Deleting them costs marketing surface and gains credibility plus measurable compliance budget on the rules that do work. §4 assumes delete/repoint — say so if you disagree, because it changes the shape of the whole release.

6. **Who is the buyer for the audit chain?** POS-01 bets the positioning on it. If the answer is "compliance/enterprise", it needs OTel export of planning/guardrail/delegation/memory decisions (the four things the GenAI conventions admit they miss) and an ASI01–ASI10 control mapping — a real product line. If the answer is "individual developers", the chain is a nice property but not a headline, and DOC-01 + honest docs are enough.

7. **What happens to the 1,359 synthesized skill rows and self-improvement as a feature?** Published evidence says self-generated skills are net-negative and that focused 2–3 module skills beat exhaustive bundles. Keeping the capability means proving positive Skill Lift on your own fixtures first (EVAL-03, XL). Deleting it retires a marketed pillar. There is no cheap middle.

## 11. CONFIDENCE & GAPS

**Well-established (reproduced by execution, most by two independent passes):** hooks are registered on zero installs (`files[]` has 47 entries with no `.claude/settings.json`; no writer in `bin/`); `plugins/mindforge/scripts/lib/` is absent; `claude plugin validate . --strict` fails with the exact precedence message while `./plugins/mindforge --strict` passes; six version locations across three distinct values; audit chain valid at 1,934 entries; 221 commands / 44 hops; 232 `.mindforge/skills` with 30 descriptions; 123 `.agent/skills`; `traces` 5,640 vs `traces_search` 2,740; `graph_edges` 0; `_migrations` 0; 1,359 of 2,038 synthesized skill rows; measured recall@10 = 0.00; the `.npmrc` token (gitignored, untracked); both config-parser regexes; `defaultArgs` replacement; the un-awaited rollback; `RevOpsAPI` unmounted; the policy engine loading exactly 1 PERMIT; the `Write(~/.ssh/**)` startup warning and the dead pipe deny rule (both empirically); `mcp-server` and `sdk` both published; `mindforge-cc` dist-tags `latest/stable/rc/alpha`.

**Uncertain / conflicting.** (a) **PreToolUse hook timeout semantics** — one live probe on 2.1.233 observed fail-open, a binary-string reading of the same build states "The tool call was not executed". Unresolved; both agree the unit is seconds. Measure before changing. (b) Whether `SubagentStart` fires for workflow-spawned agents — the docs say neither way; AUDIT-01 must verify empirically. (c) The June-2026 MCP SDK RCE disclosure is single-source and unverified against a primary advisory. (d) Whether `mindforge-sdk`'s published `MindForgeMemory` has real consumers — assume yes. (e) Whether the third-party eval tooling (`skilljack-evals`, `skills-evals`, `skill-creator`) really consumes one schema verbatim; this is what makes EVAL-03 L rather than XL and is unverified.

**Not researched.** Issue-tracker/user telemetry (so nothing here is grounded in what consumers actually use); the 218 personas and 184 subagent-pack files; the browser/`bin/browser` subsystem; the 7,349 LOC of shipped Python beyond noting it has no declared runtime, linter or test; the 10 subagent marketplace plugins with independently hand-versioned entries (same drift class as VER-01, no proposal covers them); actual token-cost measurement of the installed default profile (SKILL-03 depends on it); and whether any consumer depends on current buggy behaviour (`cwd: ROOT`, `--no-verify`, deep `require` of `bin/…`) — assume some do, and stage the breaks.
